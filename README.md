# Code Atlas

ローカルのPython、JavaScript、TypeScriptリポジトリを読み取り、ASTからコード構造と関係をブラウザで確認します。コードを実行せず、解析結果はローカルで処理します。

## 起動

Python 3.10以降が使える環境では、リポジトリのルートで次を実行します。

```text
python server.py
```

サーバーは `http://127.0.0.1:8765` で起動し、既定ではブラウザを自動で開きます。ポートを変える場合やブラウザを開きたくない場合は、次のように指定します。

```text
python server.py --port 9000
python server.py --no-browser
python server.py --no-browser --port 9000
```

Windowsでは `start.bat` も利用できます。`python`、`py`、Codexに同梱されたPythonランタイムの順で利用可能な実行環境を検出します。JavaScript / TypeScript解析を有効にするには、必要な依存を取得してから実行します。

```text
npm install
start.bat
```

`start.bat` は npm を自動実行しません。Python標準ライブラリだけでサーバーを起動できます。

## 使い方

UIからフォルダを選択するか、ローカルパスを入力して解析します。フォルダ選択ではブラウザのファイルアクセス制約に合わせてファイルを読み込み、ローカルパスではサーバーが指定フォルダを読み取ります。

中央のキャンバスは、最初にリポジトリと直下のフォルダ／ファイルだけを骨格として表示します。カードの「展開」を押すと、フォルダからファイル、ファイルからクラス／関数、クラスからメソッドへと、見たい枝だけを同じキャンバス上に追加できます。「しまう」でその枝だけを非表示にでき、ページ切り替えは発生しません。実際に解析できた呼び出しと継承は、現在見えている最も詳しいノード同士へ集約して表示します。

ファイルツリーはサイドバーに残し、検索したシンボルを選ぶと、そのシンボルまでの枝だけがキャンバス内で自動的に開きます。「構造＋関係」では所属・呼び出し・継承を一緒に表示し、「関係だけ」では同じノード配置を保ったまま所属線だけを隠します。線上を始点から終点へ進む発光パルスで方向を確認でき、呼び出しに紐づく長いコメントは線または関係ノードへホバーした時だけカードの前面に表示されます。

```text
サイドバー: ファイルツリー
              │
中央: リポジトリ ─ フォルダ ─ ファイル
                              └ クラス ─ メソッド
       （必要な枝だけ展開。呼び出し・継承も同じ場所に表示）
```

シンボルを選ぶと、パラメータ、型、既定値、戻り値、ソースを確認できます。解析結果はJSONとして保存できます。

### バージョン付きプロジェクト

`v000`、`v001` のような同一プロジェクト内のバージョンフォルダを含むパスを開くと、プロジェクトとバージョンを自動認識します。全体を解析したうえで、バージョンを `project-select` で選び、`module-select` からそのバージョンのファイルを選択します。版内の import は同じ版のファイルで解決し、表示範囲外の呼び出し線は非表示になります。空のバージョンも一覧に表示されますが、選択できません。

`include-tests` を有効にするとテストファイルを表示対象へ含められます。`show-comments` を切り替えると、呼び出しエッジに紐づくコメントの表示を制御できます。カードはリポジトリ＝紫、フォルダ＝黄、ファイル＝青、関数・メソッド＝緑で区別します。構造図は左から右へ流れるレイアウトです。

ヘッダー両端のサイドバーアイコンで左右のパネルを折りたためます。パネル境界をマウスでドラッグして幅を調整でき、境界にフォーカスした状態で左右キーでも変更できます。中央キャンバス下部で「縦間隔」152〜640px（初期値168px）と「横間隔」292〜900px（初期値338px）を調整できます。数値はカード自身の寸法を含む位置の間隔です。調整パネルの文字や余白からドラッグしても図全体を動かせます。開閉状態・幅・縦横の間隔と最後に開いたローカルパスは、次回の起動時にも復元されます。狭い画面ではパネルを下段や縦並びに切り替えます。

構造図では所属の深さで列を揃え、同じ親の子孫をまとめます。フォルダ／ファイルは名前順、定義はソース行順、引数は宣言順です。呼び出し・継承の線が増えても、この並びを変更しません。詳しい判断と配置ルールは [レイアウト設計](docs/LAYOUT_DESIGN.md) に記録しています。

通常コメントと docstring は既存コードから自動引用します。任意で明示できる Python hook は次の形式です。

```text
# @atlas-edge callee: 説明
callee(...)
```

`@atlas-edge callee:` の直後にある statement の対象 call だけがエッジへ紐づきます（任意のPython hook）。エッジを選択すると、説明と出典のパス・行番号を確認できます。説明は生成せず、Pythonの通常コメント・docstringと、JavaScript / TypeScriptのjsDocを既存コードから自動引用します。一般的なJavaScript / TypeScriptの `//` コメントは対象にしません。

## 制限と解析の範囲

- 最大1,200ファイル
- 1ファイルあたり最大512 KiB
- 合計最大16 MiB
- `.git`、`node_modules`、`__pycache__`、仮想環境などの生成物・依存フォルダは除外
- Pythonの標準ライブラリは構造解析の対象外で、import先を実行しない
- 動的な呼び出し、複雑なalias、re-exportは静的解析で解決できない場合がある
- `tsconfig.json` の `baseUrl` / `paths` による別名解決、複雑な再export（`export *` や段階的なre-export）、動的dispatchは完全には追跡しない
- JavaScript / TypeScriptでは、型だけのimportやファイル間の型関係は構文上の情報として扱い、実行時のモジュール解決は行わない
- 構文エラーやサイズ上限による除外などは警告として表示し、読めるファイルの解析を続ける。未解決の呼出しは線を表示しない
- コードや解析結果を外部サービスへ送信しない

Python解析の単体テストは次で実行できます。

```text
python -m unittest discover -s tests -v
npm run test:js
```

サーバーは標準ライブラリの `http.server` で動作します。JavaScript / TypeScriptのAST解析には npm 依存を使います。

ブラウザでの操作検証は `npm run test:ui` で4つのスモークテストを実行できます。サーバーを起動し、PlaywrightとMicrosoft Edgeが使える環境で実行してください。`CODE_ATLAS_URL` で接続先を、`PLAYWRIGHT_MODULE` でPlaywrightのモジュールパスを指定できます。版付きプロジェクトの検証も自己完結したfixtureを使います。検証画像は `artifacts/` に出力され、Gitには含めません。

解析処理は [Python ast](https://docs.python.org/3.12/library/ast.html) と [TypeScript Compiler API](https://github.com/microsoft/TypeScript/wiki/Using-the-Compiler-API) を使用しています。解析全体の組み立ては `code_atlas/analysis.py`、言語別処理は `python_parser.py`、`javascript_parser.py`、`js_parser.cjs` にあります。従来の `analyzer.py` は互換APIの入口として利用できます。
